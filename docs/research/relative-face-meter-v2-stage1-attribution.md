# v2 阶段1：原 RAW 与纯场景规则的归因

2026-11-10。**v1 保留为当前候选；v2 仍为研究。** 本阶段不修改生产测光默认、材料模型或正式解码器，不进入阶段2参数设计；仅工具在独立临时树注入实验。仅保存到2.0研究分支的阶段提交，没有合并或推送。

## 设计与实际消费

同一批16张，三臂均为原RAW解释、Portra 400 / Supra、胶片曝光补偿0、产品 print exposure compensation=false、默认颗粒/halation/glare。

- A：原 balanced，复用原扩展16张批次 JPEG，逐字节核对。
- B：v1 当前候选，复用同批原 JPEG，逐字节核对；首尾SHA清单确认16张原图未变。
- C：本轮新渲染的 v2 **纯场景规则**。不设脸目标、不运行 Vision、不读取脸文件，不设置 `FRAMEMATTER_RAW_SHADOW_BIAS`，保留原 shadowBias / baseline / decoder exposure0 / as-shot WB。场景规则与冻结v2相同，2EV预算不变。

C 全部通过真实应用CLI让引擎消费源文件全尺寸，随后正常导出1024长边sRGB JPEG；逐张 native 事件核对实际曝光、全尺寸、comp0和 print compensation=false。所有C测得的原 balanced EV 与A旧参考一致（1e-9内）。解码 trace 核对原 shadow、baseline、WB、exposure0；参数回读仅允许随机 filmEdge frameSeed 差异。A/B无本批重新渲染之意；其原balanced/v1 JPEG来自扩展批次，decoder trace 是后来原RAW批次的交叉旁证，已在manifest明确标注。

一个新build的原balanced native控制（01）也复现旧EV。默认glare随机，因此不声称新JPEG与旧JPEG逐像素一致，也不把细小像素差分当单因果证据。

## 实测结果

规则在15/16张产生非零降档，8张触发2EV封顶。它衡量相对高光分布，不是已证实的“过曝检测”；普通有高光的场景也可达到显著降档。相对阈值去掉了v1的绝对Eb门槛，同时2EV上限又低于v1已有6EV保护，造成两个方向的失败：

- 05/08/09/10/11/16等主体明显变暗。08脸部ROI中位L*从44.9降到16.0，而窗户仍87.4；这是显著主体代价，不能据此称高光保护成功。
- 02/06在纯场景v2中比v1亮4EV。02车身ROI仍3.6，天空从81.9到87.4；抬亮未恢复该暗区细节。02/06的floor占比分别64.46%/32.24%，显示原RAW测光样本大量落在floor附近；这是输入解释影响统计的线索，不足以单凭此证明decoder错误或修改RAW默认。
- 07变化约−0.0004EV，15不变。01比v1亮0.175EV，不能为它单独添加规则。
